# ④ 융합 (스마트팩토리·MES·제조 AX)

## 직무군 개요: 융합

- **하는 일**: 새 시스템 구축보다 **레거시 MES와 설비 연동의 운영·고도화(SM)** 비중이 크다. 공장이 멈추지 않게 유지하는 일이 대부분이고, AI는 품질 예측·예지보전 같은 신규 조직에 몰려 있다.
- **세부 직무와 기술 스택**
  - 스마트팩토리(제조사 DX·IIoT·FA): 설비 데이터 수집, PLC/OPC UA/MQTT 연동, HMI. Python·FastAPI·React·MQTT.
  - MES 엔지니어(개발/SM): MES 화면·기능, 쿼리, 인터페이스, 장애 대응. C#/.NET·Java·Oracle/MSSQL.
  - 제조 AX 엔지니어: 품질 예측, 예지보전, 대시보드, 데이터 파이프라인. Python·SQL·ML·BI.
- **핵심 증거 문법**: 설비 신호 → 데이터 → 화면/분석 → 현장 개선(전후 비교).
- **AI 경험의 무게**: 높음, 단 **제조 맥락으로 재해석할 때만**. 기술 나열은 운영 현실을 모르는 신호로 읽힌다.
- **당락 요인**: "자격증 여러 개보다 실제 데이터를 다룬 프로젝트 하나"(현직자 공통 의견). 공정·MES 흐름 이해(PLC → 설비 데이터 → MES → ERP), 학교 프로젝트와 현장의 차이를 인정하는 적응 의지.
- **직무명이 흩어져 있다**: 생산기술, 자동화, 설비기술, MES 운영, 제조 IT, DX. 직무명 하나로만 찾지 않는다.

## 확인 항목: 융합

공고가 요구하는 기본 요건이다. 못 채워도 지원은 한다. 매처는 충족 여부만 표시하고, 작성기는 부족한 요건을 먼저 꺼내지 않는다.

- 학력: 대기업 SI는 학사 확인 필요. 학력 무관 MES 운영 공고, 전문학사 허용 정비 직무도 있다
- 정비 성격 직무(예: 제철소 전기설비 정비)는 **전기 분야 자격증 필수**
- 근무지(지방 공장 상주·이동 가능 여부)
- 경력 공고는 2년 이상인 경우가 많다

## 작성 지침: 융합

**반드시**
- "설비(PLC·센서·모터) → 신호·데이터 → 도구(Python 등) → 현장 사용자"를 한 흐름으로 쓴다. **실제로 연결된 경험이 있을 때만** 이 흐름을 주장한다.
- 성과는 개선 전후 비교로 쓰고, 가상 데이터를 썼다면 반드시 밝힌다.
- LLM·RAG 같은 기술은 작업표준서·설비 매뉴얼·불량 이력 검색처럼 제조 문제로 바꿔 말할 수 있을 때만 앞에 둔다.
- 운영(SM)을 존중하는 태도를 보인다. 공장을 멈추지 않는 것이 우선이라는 이해.
- 지원 회사 업종(철강·자동차 부품·EMS·이차전지 등)을 언급한다.
- 근무지 이동·상주 가능하면 명시한다.

**금지**
- "AI로 미래 공장" 같은 추상 서술
- 제조 문제와 연결되지 않는 기술 나열
- "신규 개발만 하고 싶다"는 인상
- 전후 비교 없는 성과, SQL 언급 부재(MES 지원 시)
- 해외 현장을 고생담으로만 쓰기, 짧은 현장 경험 과장
