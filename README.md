# resume-agent

회사마다 이력서와 자기소개서를 새로 고쳐 쓰는 일이 생각보다 오래 걸려서, 이 과정을 자동화하려고 만들고 있습니다.
전에 주간회고 블로그 자동화 앱을 만들면서 "AI는 내가 준 사실만 쓰게 해야 한다"는 걸 배웠는데, 그 원칙을 취업 서류에도 그대로 가져왔습니다.

## 만들려는 것

1. 제 기본 정보와 이력서·포트폴리오를 **경험 카드**(상황·과제·행동·결과·배운 점)로 정리합니다. AI는 이 카드에 있는 사실만 글에 쓸 수 있습니다.
2. 지원할 회사의 공고(URL·PDF·HWP 등)를 넣으면 회사를 조사하고, 공고에서 키워드·인재상·문항을 뽑습니다.
3. 회사에 맞춘 이력서와 자기소개서 초안을 쓴 뒤, 회차마다 관점을 바꿔 **5번 검증**합니다.
   사실성 → 문항 적합·구조 → 직무·회사 적합 → 문장 품질 → 일관성
4. 마지막으로 글 쓴 모델과 **다른 모델**이 인사담당자 입장에서 점수, 판정, 면접 예상 질문을 냅니다.
5. 채용 사이트 입력칸까지 채워줍니다. 로그인과 제출 버튼은 제가 직접 누릅니다.

비슷한 오픈소스 중에는 대량으로 자동 지원하는 도구가 많았습니다. 그런데 채용 담당자들이 그런 지원서를 스팸으로 거른다는 기사를 보고, 저는 한 번에 한 회사씩 품질 위주로 가기로 했습니다.
자세한 설계와 진행 순서는 [PLAN.md](PLAN.md)에 정리했습니다.

## 진행 상황

- [x] 1단계: 파일 파서(PDF·DOCX·HWP·HWPX·URL), 경험 카드 화면, 모델 설정
- [x] 프롬프트 기반: 카드형 화면, 작성 원칙 39개(유튜브 100편 조사), 직무군 6개 프롬프트
- [x] 무료 등급만으로 하루 30개: 시간 제한·재시도·예비 모델·사용량 기록·하루/분당 상한
- [x] 2단계: 공고 분석(+적합도) → 회사 리서치 → 초안 → 코드 검사 → 검증 → 수정
- [x] 3단계: 정밀 모드(5차 검증을 하나씩), 회차마다 확인, 수정 전후 비교·되돌리기
- [x] 4단계: 맞춤 이력서, 인사담당자 평가, 면접 질문, DOCX·PDF, 지원 상태 관리
- [x] 5단계: 채용 사이트 자소서 입력칸 채우기 (제출은 직접)
- [ ] 6단계: 실제 공고 여러 개로 시험하고 다듬기
- [ ] 보류: 조건에 맞는 공고 추천

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

처음이라면 홈의 **샘플로 체험하기**를 눌러 보세요. 가상 인물·가상 공고·미리 만든 결과가 들어 있고, 화면 위에 **16단계 튜토리얼**이 떠서 실제로 쓰는 순서대로(내 경험 정리 → 공고 넣기 → 결과 확인·수정 → 내보내기·사이트 입력) 한 단계씩 안내합니다. 해낸 단계는 자동으로 체크됩니다. 체험 데이터는 `data_demo/`에 따로 있어서 실제 데이터와 섞이지 않습니다.

실제로 쓰려면 **설정** 페이지에서 Gemini API 키를 넣습니다(기본 구성은 무료 등급만 씁니다).
개인정보와 API 키는 `data/` 폴더에만 저장되고, 이 폴더는 깃에 올라가지 않습니다.
