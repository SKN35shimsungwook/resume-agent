# resume-agent

회사마다 이력서와 자기소개서를 새로 고쳐 쓰는 일이 생각보다 오래 걸려서, 이 과정을 자동화하려고 만들고 있습니다.
전에 주간회고 블로그 자동화 앱을 만들면서 "AI는 내가 준 사실만 쓰게 해야 한다"는 걸 배웠는데, 그 원칙을 취업 서류에도 그대로 가져왔습니다.

## 만들려는 것

1. 제 기본 정보와 이력서·포트폴리오를 **경험 카드**(상황·과제·행동·결과·배운 점)로 정리합니다. AI는 이 카드에 있는 사실만 글에 쓸 수 있습니다.
2. 지원할 회사의 공고(URL·PDF·HWP 등)를 넣으면 회사를 조사하고, 공고에서 키워드·인재상·문항을 뽑습니다.
3. 회사에 맞춘 이력서와 자기소개서 초안을 쓴 뒤, 회차마다 관점을 바꿔 **5번 검증**합니다.
   사실성 → 문항 적합·구조 → 직무·회사 적합 → 문장 품질 → 일관성
4. 마지막으로 글 쓴 모델과 **다른 모델**이 인사담당자 입장에서 점수, 판정, 면접 예상 질문을 냅니다.
5. 채용 사이트 입력칸까지 채워줍니다. 로그인과 제출 버튼은 제가 직접 누릅니다.

비슷한 오픈소스 중에는 대량으로 자동 지원하는 도구가 많았습니다. 그런데 채용 담당자들이 그런 지원서를 스팸으로 거른다는 기사를 보고, 저는 한 번에 한 회사씩 품질 위주로 가기로 했습니다.
자세한 설계와 진행 순서는 [PLAN.md](PLAN.md)에 정리했습니다.

## 진행 상황

- [x] 1단계: 파일 파서(PDF·DOCX·HWP·HWPX·URL), 경험 카드 화면, 모델 설정
- [x] 프롬프트 기반: 카드형 화면, 작성 원칙 39개(유튜브 100편 조사), 직무군 6개 프롬프트
- [x] 무료 등급만으로 하루 30개: 시간 제한·재시도·예비 모델·사용량 기록·하루/분당 상한
- [x] 2단계: 공고 분석(+적합도) → 회사 리서치 → 초안 → 코드 검사 → 검증 → 수정
- [x] 3단계: 정밀 모드(5차 검증을 하나씩), 회차마다 확인, 수정 전후 비교·되돌리기
- [x] 4단계: 맞춤 이력서, 인사담당자 평가, 면접 질문, DOCX·PDF, 지원 상태 관리
- [x] 5단계: 채용 사이트 자소서 입력칸 채우기 (제출은 직접)
- [x] 6단계: 가상 인물 30명 × 실제 공고 30개로 시험하고 다듬기
- [x] 지원 관리: 공고의 급여·근무지·복지를 근거 문구와 함께 정리, 지원 현황(상태·일정·할 일·메모)을 SQLite에 저장, 다 쓴 결과를 `날짜_회사_직무.pdf`로 보관
- [x] 인사담당자 첨삭 메뉴: 지적된 문장을 노랗게 표시하고, 지적대로 고친 뒤 다시 채점
- [x] 사실 검사 강화: 문장마다 근거 카드를 달게 하고, 카드에 없는 숫자나 근거 없는 사실 문장을 코드로 잡음
- [x] 개인정보 가리기: 무료 등급을 그대로 쓰되, 보내기 전에 이름·연락처를 가리고 받은 답에서 되돌림
- [ ] 보류: 조건에 맞는 공고 추천

### 30명 시험에서 배운 것

처음 돌렸을 때 인사담당자 평균 점수는 59점이었고, 문항당 글이 217자밖에 안 됐습니다. 원인을 찾아보니 수정 단계가 문장을 고치지 않고 지워 버려서 글이 평균 31% 줄고 있었습니다.
분량 목표를 코드로 정하고, 많이 줄어들면 한 번 더 고치게 바꿨더니 다시 돌린 24개에서 평균 78점, 문항당 575자가 됐습니다. 대신 공고 하나에 드는 호출은 9번에서 14번으로 늘었습니다.
같은 글을 다시 채점하면 점수가 평균 10점 정도 흔들린다는 것도 확인했습니다. 그래서 10점이 넘는 차이만 개선으로 보기로 했습니다.
코드를 정리한 뒤에는 시험 때 녹화한 AI 응답을 그대로 다시 넣어서 30개 모두 같은 결과가 나오는지 확인합니다(`pytest`와 재생 시험은 호출 0번).

## 실행

```bash
pip install -r requirements.txt
streamlit run app.py
```

처음이라면 홈의 **하나씩 따라하기 → ▶ 시작**을 누르세요. 가상 인물 '김예시'가 되어 9단계(이력서 넣기 → 경험 카드 → 공고 넣기 → 자소서 쓰기 → 검사 결과 → 고치기 → 파일 받기)를 **한 화면에 하나씩** 해 봅니다. 버튼 누르고 → 결과 보고 → 다음. 체험 데이터는 `data_demo/`에 따로 있어서 실제 데이터와 섞이지 않습니다.

실제로 쓰려면 **설정** 페이지에서 Gemini API 키를 넣습니다(기본 구성은 무료 등급만 씁니다).
개인정보와 API 키는 `data/` 폴더에만 저장되고, 이 폴더는 깃에 올라가지 않습니다.
다만 Gemini 무료 등급은 약관상 입력한 내용이 서비스 개선에 쓰이고 사람이 볼 수도 있습니다. 유료로 바꾸는 대신, AI에 보내기 직전에 이름·이메일·전화번호·주민번호를 `[이름]`·`[이메일]` 같은 자리표시로 바꾸고 답이 오면 원래대로 돌려놓게 했습니다. 집 주소나 학교처럼 더 가리고 싶은 단어는 **설정 → 개인정보 가리기**에 적으면 됩니다. 경력 내용 자체는 글을 쓰려면 필요해서 그대로 보냅니다.

시험은 아래처럼 돌립니다(API 호출 없음).

```bash
python -m pytest tests -q
```
