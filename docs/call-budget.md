# 호출 예산: 하루 공고 30개를 끊기지 않고

목표: 하루에 공고 30개를 처리하면서, 한두 개 하다가 호출 한도나 오류로 멈추지 않는다. (2026-11-02)

## 1. 처음 설계대로 하면 너무 많다

| 단계 | 호출 수 |
|---|---|
| 회사 리서치 + 공고 분석 | 2~4 |
| 매칭 + 초안 | 2 |
| 5차 검증(5) + 수정(5) | 10 |
| 인사담당자 평가 | 1 |
| **공고 1개** | **약 15~17** |
| **하루 30개** | **약 450~510** |

무료·저가 요금제의 하루 요청 한도는 모델마다 수백 건 수준이라는 자료가 있다. 다만 자료끼리 숫자가 다르고 Google 공식 페이지로 확인하지 못했다. 그래서 숫자를 믿고 설계하지 않고, **실제 사용량을 기록해 보면서 맞춘다.**

### 실제 한도와 모델 구성 (2026-11-02, AI Studio·OpenAI 대시보드에서 확인)

**원칙: 무료 등급 안에서만 돌린다. OpenAI 크레딧($19.12)은 자동으로 쓰지 않는다.**

| 역할 | 모델 | 분당 요청 | 분당 토큰 | 하루 요청 | 설정한 상한 |
|---|---|---:|---:|---:|---|
| 작성 | Gemini 3.5 Flash Lite | 15 | 25만 | 500 | 분당 13, 하루 450 |
| 평가 | **Gemini 3.1 Flash Lite** (작성과 세대가 다름, 2026-11-03 변경) | 15 | 25만 | 500 | 분당 13, 하루 450 |
| 평가 예비 | Gemma 4 26B (다른 계열, 한도 넉넉) | 30 | **1.6만** | 14,400 | 분당 2 (토큰 한도 때문) |
| 작성 예비 | Gemini 3.1 Flash Lite (평가와 한도 공유) | 15 | 25만 | 500 | (위와 같음) |
| 쓰지 않음 | Gemini 3.8 Flash | 5 | 25만 | 20 | 하루 20이라 주력 불가 |
| 수동 선택만 | gpt-4o-mini | 5,000 | 200만 | — | 유료, 자동으로 넘기지 않음 |

- 시험 결과: 3.5 Flash Lite 3초대 정상, Gemma 4 26B 4.6초 정상. 3.1 Flash Lite와 3.8 Flash는 시험 당시 503(수요 과다), Gemma 4 31B는 504(시간 초과). 무료 모델은 이런 일시 장애가 잦아서 재시도·예비 모델이 꼭 필요하다.
- Gemma는 분당 토큰이 1.6만뿐이라 프롬프트가 길면 분당 1~2회만 된다. 평가 90회면 45~90분 걸린다 → 공고를 줄 세워 자리를 비운 사이 돌리는 방식과 맞는다.
- 모든 무료 한도가 차면 **유료로 넘기지 않고 멈춘 뒤 저장**하고, 다음 날(태평양 시간 자정 기준 초기화) 이어서 한다.
- `gemini-2.5-flash`는 이 키로 쓸 수 없다(404).

**일반 모드 하루 30개 계산**: 작성 공고당 2~4회 → 60~120회(하루 450 중 여유). 평가 공고당 3회 → 90회(Gemma 하루 14,400 중 여유, 대신 느림).

## 2. 줄이는 방법

### ① LLM이 필요 없는 검사는 코드로 (호출 0)

검증 규칙 중 상당수는 규칙만 있으면 코드로 확인할 수 있다.

| 규칙 | 코드로 하는 방법 |
|---|---|
| FC-4 글자 수 제한, 문항 누락 | 길이 계산, 문항 목록 대조 |
| FC-3 회사명·직무명 오기재 | 다른 회사명이 들어 있는지 문자열 검사 |
| FA-1 근거 카드 id | 문장마다 카드 id가 있고 실제로 존재하는지 |
| FA-2 수치 | 글 속 숫자가 경험 카드에 있는 숫자인지 |
| WR-3 상투어 | 금지 표현 목록 검사 ("~역량을 기를 수 있었습니다" 등) |
| MA-1 문항 간 경험 중복 | 문항별 주 카드 id 비교 |

### ② 5차 검증은 "관점 5개"로 유지하되 호출은 묶는다

| 묶음 | 담는 관점 | 모델 |
|---|---|---|
| 코드 검사 | 글자 수·회사명·근거 id·수치·상투어·중복 | 없음 |
| 검증 A | 1차 사실성 + 5차 일관성 | 평가 모델 |
| 검증 B | 2차 구조 + 3차 직무·회사 적합 + 4차 문장 | 평가 모델 |

### ③ 위반이 없으면 수정 회차를 건너뛴다

검증에서 위반 0건이고 점수가 기준 이상이면 수정 호출을 하지 않는다. 수정은 최대 2회까지만 한다.

### ④ 한 번 만든 결과는 다시 만들지 않는다

- 경험 카드 요약: 한 번 만들어 모든 공고에서 재사용
- 회사 리서치·공고 분석: 회사·공고별로 저장해서 같은 회사 다른 공고에 재사용
- 단계마다 결과를 파일로 저장해서, 중간에 멈추면 **멈춘 단계부터 다시 시작**

## 3. 두 가지 모드

| 모드 | 흐름 | 공고 1개 호출 | 하루 30개 |
|---|---|---|---|
| **일반** (기본) | 분석(+적합도) 1 → 회사 리서치 0~1(회사별 1회) → 초안 1 → 코드 검사 → 검증 A·B 2 → 수정 0~1 → 맞춤 이력서 1 → 인사담당자 1 → 추가 수정 0~1 | **6~9** | **180~270** |
| **정밀** (꼭 붙고 싶은 곳) | 처음 설계대로 5차 검증을 하나씩 | 15~17 | 몇 곳만 |

선택 사항: 30개를 모두 쓰기 전에 **적합도 스크리닝**(공고당 저가 모델 1호출)을 먼저 해서, 점수가 낮은 공고는 작성 단계를 건너뛸 수 있다.

## 4. 멈추지 않게 하는 장치

| 장치 | 내용 |
|---|---|
| 응답 시간 제한 | 한 호출이 일정 시간(기본 90초) 안에 안 오면 끊고 재시도 |
| 재시도 | 429(한도 초과)·5xx·시간 초과는 기다렸다가 다시 시도(점점 길게, 최대 4번) |
| 사용량 기록 | 호출마다 날짜·모델·토큰을 `data/usage.jsonl`에 기록, 화면에 오늘 사용량 표시 |
| 하루 예산 | 모델별 하루 호출 상한을 설정에 두고, 넘기 전에 멈추고 알림 |
| 다른 모델로 넘기기 | 한쪽 한도가 차거나 장애면 설정한 **무료** 예비 모델로 이어서 진행. 유료로는 넘기지 않음 |
| 중간 저장 | 단계별 결과 저장 → 다시 실행하면 이어서 |


## 평가 모델 비교 (2026-11-03, 같은 가상 공고)

| | Gemma 4 26B | Gemini 3.1 Flash Lite |
|---|---|---|
| 공고 1개 처리 시간 | 526초 (평가 호출당 2~4분, 504 잦음) | **약 33초** |
| 사실 검증 (그대로 쓸 때) | 지어낸 문장 일부를 잡음 | 100점·위반 0건 — **놓침** |

3.1은 빠르지만 사실 검증을 그대로 맡기면 느슨해서, 모델 성능에 기대지 않는 장치 두 개를 더했다.

1. **근거 문구 대조**: 검증 모델이 주장마다 경험 카드·공고에서 문구를 그대로 복사해 오고, 그 문구가 원문에 실제로 있는지 **코드가 글자 단위로 대조**한다. 없으면 FA-1.
2. **낯선 낱말 검사**: 답변 문장에 카드·공고에 없는 낱말이 몰려 있으면 표시한다(포부 문장 제외). 초안에서 걸린 것은 수정 단계로 넘기고, **최종본에도 한 번 더** 돌려 남은 의심 문장을 화면에 경고로 띄운다.

결과: 최종본에서 지어낸 문장이 사라졌다. 대신 사실이 부족한 문항은 답변이 짧아진다(인사담당자 58점) → 확인 질문에 답해 경험 카드를 채우는 것이 점수를 올리는 길이다.
